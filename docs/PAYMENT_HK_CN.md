# 香港服务器 + 境外域名接入微信/支付宝支付方案

## 1. 先给结论

服务器位于香港、域名在 Cloudflare，不会自动获得微信支付或支付宝的官方商户资格。支付资格取决于**收款主体、注册地、业务类型、KYC、网站内容、风控和通道审核**，不是服务器所在地。

对当前 XDD API：

1. 有**大陆公司主体和可备案网站**时，最接近“官方直连”的方案是微信支付 APIv3 + 支付宝开放平台。
2. 只有**香港公司主体**时，官方跨境路线应评估 WeChat Pay Global / Tenpay Global 和 Antom（支付宝跨境），但都需要单独申请商户号、审核和接口适配。
3. 希望更快上线时，可评估 Stripe HK 或 Airwallex HK。它们是持牌收单/聚合机构，不是微信或支付宝官方直连，不能对外宣称“官方微信/支付宝商户”。
4. 个人主体通常拿不到官方商户 API，只能使用第三方聚合或卡密平台。此类方案不是官方通道，存在冻结、跑路、退款和合规风险。
5. 大陆微信 APIv3、大陆支付宝开放平台商户号通常不能直接套用于香港主体，也不能假设现有大陆凭据可复用。

## 2. 先区分三种“微信/支付宝支付”

| 类型 | 含义 | 是否“官方直连” | 典型主体 | 与当前 Bridge 的关系 |
| --- | --- | --- | --- | --- |
| 大陆官方直连 | 微信支付 APIv3、支付宝开放平台商户 | 是 | 大陆企业、个体工商户等符合条件主体 | 需要 Bridge 新增对应适配，或使用 Sub2API 原生支付 |
| 官方跨境收单 | WeChat Pay Global / Tenpay Global、Antom | 是，按跨境产品签约 | 香港/境外企业 | 需要单独申请和开发跨境接口 |
| 持牌收单/聚合机构 | Stripe、Airwallex 等 | 不是微信/支付宝直连 | 香港或支持地区的企业 | 通过其收单能力展示钱包支付方式，需确认具体产品 |
| 第三方聚合/卡密 | EasyPay、Dujiao 第三方通道、发卡平台 | 通常不是 | 平台审核通过的商家 | 可作为过渡，不应冒充官方通道 |

> “用户看到微信/支付宝图标”不等于商户直接接入了微信或支付宝。判断标准是实际合同、商户号、API 类型和结算主体。

## 3. 按主体选择路线

| 主体条件 | 推荐路线 | 优势 | 主要限制 |
| --- | --- | --- | --- |
| 大陆公司 + 网站可备案 | 微信支付 APIv3 + 支付宝开放平台 | 最接近官方直连，国内用户体验最好 | 需要营业执照、对公账户、网站备案、业务审核；AI API/预付费额度业务可能被重点审核 |
| 香港公司 + 香港银行账户 | Antom / Tenpay Global 官方跨境；并行评估 Stripe HK、Airwallex HK | 与香港主体匹配，可覆盖跨境用户 | 跨境钱包审核周期和材料更多；Stripe/Airwallex 不是官方直连 |
| 香港公司，暂时没有银行账户 | 先确认能否完成 KYC；否则不要先开发支付 | 避免做出无法上线的接口 | 无合规收款账户时，官方和持牌机构都可能拒绝 |
| 境外其他公司 | Stripe/Airwallex 支持地区优先 | 接入成熟，国际卡和多币种能力较强 | 微信/支付宝可用性取决于地区、币种和账户审核 |
| 个人/无公司主体 | 不建议作为长期正式支付方案 | 上线快 | 无法稳定获得官方商户资格，资金和合规风险高 |

## 4. 推荐优先级

### 路线 A：大陆官方直连（最“官方”）

适用于有大陆公司、对公账户和可备案网站的主体。

需要准备：

- 营业执照、法人/经办人身份证明、企业对公账户。
- 网站 ICP 备案、域名实名和可访问的产品/价格/服务条款页面。
- 微信支付商户号、AppID、APIv3 密钥、商户证书/平台证书。
- 支付宝开放平台应用、商户号、应用私钥、支付宝公钥。
- 明确的业务说明、退款政策、客服联系方式和风控流程。

技术注意：

- 微信和支付宝是两套独立接口，不能共享一套密钥。
- 回调域名必须是公网 HTTPS，并配置到商户平台允许列表。
- Bridge 需要实现支付创建、回调验签、主动查单、退款和对账。
- `xddapi.org.uk` 当前是境外域名，大陆官方通道审核通常会核验备案和域名归属，不能假设能通过。
- 如果使用 Sub2API 原生支付宝/微信支付，不要再同时开放 Bridge，避免双入口。

### 路线 B：香港主体的官方跨境收单

适用于香港公司，希望服务境外用户并使用微信/支付宝。

优先评估：

1. **WeChat Pay Global / Tenpay Global**：官方跨境微信收款路线。
2. **Antom（支付宝跨境）**：官方跨境支付宝收单路线。

这类方案通常要求：

- 香港公司注册证明、商业登记、董事和受益人 KYC。
- 香港银行账户或平台支持的结算账户。
- 网站、App 或小程序的产品说明、价格、退款、隐私和服务条款。
- 真实跨境业务证明，不能是空壳或无说明的 API 转售。
- 单独申请商户号和 API 凭据，不能复用大陆 APIv3 商户配置。

优缺点：

- 优点：官方跨境产品，品牌和资金路径更清晰。
- 缺点：审核和接入周期较长，通常需要定制适配和真实交易验收。
- 当前 Dujiao 固定镜像不一定有对应适配器，不能只看后台是否显示“微信/支付宝”。

### 路线 C：持牌收单机构（上线更快，但不是官方直连）

#### Stripe HK

- Stripe 官方文档支持 Alipay、WeChat Pay 等支付方式。
- 香港属于支持地区，但是否开放具体钱包、币种和结算能力取决于账户审核。
- Dujiao-Next 有 `stripe` 通道类型，适合先做小额验证，但必须确认当前固定镜像是否支持目标钱包和回调。
- 对外应表述为“Stripe 收银台支持的支付方式”，不要表述为“微信/支付宝官方直连”。

#### Airwallex HK

- 面向香港和跨境商户，适合有香港公司的主体。
- 支持多币种收单和结算，具体微信/支付宝能力以账户实际开通结果为准。
- Sub2API 原生支付已有 Airwallex 适配；Dujiao 当前没有原生 Airwallex 适配。
- 若坚持 Bridge 架构，需要新增 Bridge 支付适配；若使用 Sub2API 原生 Airwallex，则要关闭 Bridge 正式入口。

### 路线 D：第三方聚合或卡密（仅过渡）

适用于还没有商户资质、需要快速验证付费意愿的阶段。

必须做到：

- 页面和客服话术明确标注第三方支付，不冒充官方微信/支付宝。
- 控制单笔、日累计和余额沉淀上限。
- 保留 Dujiao 订单、Bridge 订单、平台流水和 Sub2API 余额流水。
- 准备平台冻结、延迟结算、跑路、退款和拒付的应急预案。
- 不把长期资金留在单一第三方平台。
- 不把“能发卡”误解为“具备官方支付资质”。

## 5. 与当前 Bridge 架构的衔接

当前生产链路：

```text
Sub2API 登录
  -> Bridge /shop/
  -> Dujiao-Next 订单
  -> Dujiao 支付通道
  -> Bridge 回调验签与主动查单
  -> Sub2API 幂等余额入账
```

不同支付路线的落法：

| 路线 | 推荐接法 | 是否需要改代码 | 备注 |
| --- | --- | --- | --- |
| Dujiao + Stripe | Dujiao Stripe 通道 | 通常否 | 必须确认固定镜像支持目标钱包和回调 |
| Dujiao + 第三方聚合 | Dujiao 对应通道 | 通常否 | 先确认签名、查单、退款和结算 |
| 大陆支付宝/微信官方 | Bridge 直连适配，或 Sub2API 原生支付 | 是 | 不能假设 Dujiao 的“支付宝/微信”就是官方直连 |
| Airwallex HK | Sub2API 原生或 Bridge 新适配 | 是 | 两套入口只能保留一套 |
| Antom / Tenpay Global | Bridge 新适配 | 是 | 需先拿到商户资格和 API 文档 |

设计原则：

1. **先拿到真实商户资格，再决定接哪条代码路径。**
2. **支付真伪由服务端查单确认，回调只作为通知。**
3. **金额、币种、商户订单号和幂等键必须由 Bridge 生成并保存。**
4. **同一时间只保留一个正式充值入口。**
5. **支付适配器必须同时实现创建、查单、回调验签、退款/异常处理和对账。**

## 6. 申请材料清单

通用材料：

```text
[ ] 公司注册证明和商业登记
[ ] 法定代表人/董事/受益人身份证明
[ ] 地址证明和香港银行账户信息
[ ] 网站域名所有权和 HTTPS
[ ] 产品说明、价格页、服务条款、隐私政策
[ ] 退款政策、客服邮箱/工单入口
[ ] 业务流水、用户来源和预计月交易额
[ ] 风险控制、拒付和异常订单处理流程
```

大陆官方直连额外需要：

```text
[ ] ICP 备案
[ ] 微信支付商户号和 AppID
[ ] 支付宝开放平台应用和商户号
[ ] 对公账户和结算信息
[ ] 回调域名白名单
```

跨境官方收单额外需要：

```text
[ ] 跨境业务说明和真实交易场景
[ ] 香港/境外主体 KYC
[ ] 结算币种和收款账户
[ ] 目标国家/地区与可用钱包范围
[ ] 跨境接口文档和验收用例
```

## 7. 费用、结算和额度

不要根据网上文章预先承诺固定费率。上线前必须拿到书面确认：

```text
[ ] 开户费/年费/保证金
[ ] 交易手续费和计费币种
[ ] 跨境费、换汇费和汇损
[ ] 退款费、拒付费和争议处理费
[ ] 结算周期、最低结算额和冻结规则
[ ] 单笔、日、月交易限额
[ ] 支持的支付方式、地区和币种
[ ] 回调签名、重试、主动查单和退款接口
```

AI API 转售、预付费余额和跨境服务可能被列为高风险或需补充材料，不能只按普通电商类目判断。

## 8. 合规与运营要求

- 充值余额属于预付费服务额度，必须有清晰的服务条款、有效期和退款规则。
- 不得把支付通道用于违法、赌博、欺诈、洗钱或通道禁止的类目。
- 保留订单、支付、退款、兑换、余额变更和客服记录。
- 对大额、高频、异常退款和拒付设置人工审核。
- 不保存银行卡号、CVV 或支付平台密码。
- 支付密钥只放在服务器 `.env` 或密钥管理系统，不进入 Git、前端和日志。
- 定期做四方对账：支付平台流水、Dujiao 订单、Bridge 订单、Sub2API 余额流水。

## 9. 技术验收

```text
[ ] 支付创建接口只在服务端调用
[ ] 回调签名验证通过
[ ] 伪造回调和重放回调被拒绝
[ ] 服务端主动查单金额、币种和订单号均一致
[ ] 重复回调不会重复加余额
[ ] 支付成功但入账失败会自动重试
[ ] 支付页关闭后可以从订单历史继续支付
[ ] 退款/拒付能定位到 Bridge 订单
[ ] 支付通道停用后前端不再展示
[ ] 结算币种和账务口径明确
[ ] 客服和退款入口可用
[ ] 完成一笔低金额真实订单闭环后再全量开放
```
