# 香港服务器 + 境外域名接入微信/支付宝支付方案

## 1. 先给结论

服务器在香港、域名在 Cloudflare，并不等于自动获得微信支付或支付宝的官方商户资格。支付资质取决于**收款主体、公司注册地、业务类型、KYC、风控和通道审核**，不是服务器所在地。

对当前 XDD API：

- 最务实的官方/持牌路线是：**香港公司主体 + 香港银行账户 + Airwallex HK 或 Stripe HK**。
- 需要中国大陆钱包直连能力时，再评估 **WeChat Pay Global / Tenpay Global** 和 **Antom（支付宝跨境）**。
- EasyPay、第三方卡密平台适合作为过渡，不是官方直连，也不应宣称“官方微信/支付宝”。
- 任何费率、结算周期、可用币种和是否支持 Alipay/WeChat，都以申请时合同和审核结果为准，不能预先承诺。

## 2. 方案对比

| 方案 | 主体/资质 | 微信/支付宝能力 | 与当前代码关系 | 适合程度 |
| --- | --- | --- | --- | --- |
| Airwallex HK | 香港公司、KYC、业务审核 | 取决于账户开通的本地/跨境支付能力 | Sub2API 已有 Airwallex 适配；Dujiao 当前无原生 Airwallex 适配 | 优先评估 |
| Stripe HK | 香港公司、KYC | Stripe 官方支持 Alipay、WeChat Pay 等支付方式，但是否开放取决于账户地区、币种和审核 | Dujiao 有 `stripe` 通道；需验证当前镜像是否支持目标钱包 | 优先评估 |
| WeChat Pay Global / Tenpay Global | 境外商户、跨境业务审核 | 官方跨境微信收款路线 | 通常不能复用大陆微信支付 APIv3 凭据，需要单独适配 | 有明确跨境需求时申请 |
| Antom / Alipay 跨境 | 境外商户、跨境业务审核 | 官方支付宝跨境收单 | 与大陆支付宝官方 API 不同，需要单独接入/适配 | 有明确跨境需求时申请 |
| 大陆支付宝官方 API | 大陆主体及对应资质 | 官方支付宝 | Sub2API 已有大陆支付宝适配 | 香港主体通常不可直接套用 |
| 大陆微信支付 APIv3 | 大陆主体及对应资质 | 官方微信支付 | Sub2API 已有大陆微信支付适配 | 香港主体通常不可直接套用 |
| EasyPay / 卡密平台 | 平台规则和商家审核 | 非官方直连，可能由平台代收 | 可作为过渡，不能作为长期官方方案 | 仅过渡 |

### 2.1 Airwallex HK

优点：

- 面向香港和跨境商户，适合有香港公司的主体。
- Sub2API 已有 Airwallex 支付适配，后续若切换到 Sub2API 原生收银台，改造成本较低。
- 可统一处理多币种和跨境结算。

限制：

- 需要公司注册、KYC、业务说明、网站/产品信息和风控审核。
- Alipay/WeChat 是否可用以及具体结算币种，要以 Airwallex 账户实际开通结果为准。
- 当前 Bridge 走 Dujiao，Dujiao 没有 Airwallex 适配器；若坚持 Bridge 架构，需要单独扩展支付适配，或把该支付方式切回 Sub2API 原生支付。

### 2.2 Stripe HK

优点：

- Stripe 官方提供 Alipay、WeChat Pay 等支付方式文档。
- 香港主体可申请 Stripe HK，适合国际卡和部分本地钱包。
- Dujiao-Next 有 `stripe` 通道类型，适合当前商城架构做初步验证。

限制：

- Stripe 是收单机构，不是“支付宝/微信官方商户直连”；用户看到的是 Stripe 支持的支付方式。
- 可用性、币种、结算和争议处理受 Stripe 账户审核及地区政策影响。
- 必须验证 Dujiao 当前固定镜像的 Stripe 适配是否支持目标钱包和回调。

### 2.3 WeChat Pay Global / Tenpay Global

这是官方跨境路线之一，适合有境外主体和真实跨境业务的主体。需要：

- 境外公司资质和 KYC。
- 业务场景、网站、退款和客服说明。
- 单独申请商户号和 API 凭据。
- 针对跨境接口做适配，不能直接假定大陆微信支付 APIv3 凭据可复用。

### 2.4 Antom / Alipay 跨境

Antom 面向跨境商户提供收单能力。与大陆支付宝开放平台不是同一套商户接入。需要单独申请、审核和适配，适合明确需要支付宝跨境收款的业务。

## 3. 推荐落地顺序

### 阶段 A：先完成主体和基础材料

1. 注册香港公司并开立香港银行账户。
2. 准备公司注册证明、董事/受益人 KYC、地址证明。
3. 准备业务说明、产品页面、价格页、服务条款、隐私政策、退款政策和客服联系方式。
4. 明确销售的是 API/软件服务，避免使用高风险或无法说明的类目。
5. 准备对账、发票/收据、退款和拒付处理流程。

### 阶段 B：优先申请两个通道

1. **Airwallex HK**：优先因为它适合香港主体，且 Sub2API 已有适配基础。
2. **Stripe HK**：作为备用收单和多支付方式能力，先做小额测试。

两个通道不要同时未经测试就全量开放。先各跑一笔低金额测试，确认支付、回调、退款、结算和对账。

### 阶段 C：按真实需求申请跨境钱包

只有在用户确实需要微信/支付宝、且 Airwallex/Stripe 不能满足时，再申请：

- WeChat Pay Global / Tenpay Global
- Antom / Alipay 跨境

跨境钱包通常审核更长、材料更多，且可能需要单独开发和验收。

### 阶段 D：过渡期使用 EasyPay/卡密

EasyPay 或卡密平台可以快速上线，但必须：

- 明确标注为第三方支付，不冒充官方微信/支付宝。
- 控制单笔和日累计额度。
- 保留完整订单、支付流水、兑换记录。
- 准备平台跑路、冻结、退款和拒付的应急预案。
- 不把长期资金沉淀在单一第三方平台。

## 4. 与当前 Bridge 架构如何衔接

当前生产链路是：

```text
Sub2API 登录
  -> Bridge
  -> Dujiao-Next 订单
  -> Dujiao 支付通道
  -> Bridge 回调验签和查单
  -> Sub2API 余额
```

可落地的组合：

1. **Dujiao + Stripe HK**：如果固定镜像的 Stripe 通道支持目标支付方式，配置成本最低。
2. **Dujiao + 第三方聚合支付**：用于过渡，需确认回调签名和查单能力。
3. **Sub2API 原生 Airwallex**：功能完整，但与 Bridge 是两套充值入口；不要同时启用，需单独设计统一的订单和到账口径。
4. **Bridge 直接接 Airwallex**：需要新增支付适配、回调验签、查单和幂等入账，不建议在没有明确通道审核结果前先开发。

选择原则：**先拿到真实商户资格和支付能力，再决定接哪条代码路径**。不要为了一个尚未批准的通道提前重构。

## 5. 费用、结算和额度

不要基于网上文章承诺固定数字。实际结果通常取决于：

- 公司注册地和业务类别。
- 月交易额、平均客单价、退款率和拒付率。
- 结算币种、换汇方式和结算周期。
- 是否跨境、是否涉及订阅或预付费余额。
- 风控审核和保证金要求。

上线前应向每个通道拿到书面确认：

```text
[ ] 开通费/年费
[ ] 交易手续费及计费币种
[ ] 跨境/换汇费
[ ] 退款费/拒付费
[ ] 结算周期和最低结算额
[ ] 保证金或滚动准备金
[ ] 单笔、日、月限额
[ ] 支持的支付方式和地区
[ ] 回调签名、重试和查单接口
```

## 6. 合规和运营要求

- 充值余额属于预付费/服务额度，必须有清晰的服务条款、有效期和退款规则。
- 不得把支付通道用于违法、赌博、欺诈、洗钱或通道禁止的类目。
- 保留订单、支付、退款、兑换、余额变更和客服记录。
- 对大额、高频、异常退款和拒付设置人工审核。
- 不要把用户支付信息存入 Bridge 数据库。
- 支付密钥只放在服务器 `.env` 或密钥管理系统，不进入 Git、前端和日志。
- 定期做三方对账：支付平台流水、Dujiao 订单、Bridge 订单、Sub2API 余额流水。

## 7. 技术验收

```text
[ ] 支付成功回调签名验证通过
[ ] 伪造回调和重放回调被拒绝
[ ] 服务端重新查单金额与本地订单一致
[ ] 重复回调不会重复加余额
[ ] 支付成功但入账失败会自动重试
[ ] 退款/拒付能定位到 Bridge 订单
[ ] 支付通道停用后前端不再展示
[ ] 结算币种和账务口径明确
[ ] 客服和退款入口可用
```
